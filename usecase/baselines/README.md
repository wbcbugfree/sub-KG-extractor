# NALT LSTM and Path Analogy baselines

This package evaluates LSTM and Path Analogy on five NALT branches using the
16 July 2024 release and the model builders in
`reproduction/src/models_on_labeled_decisions`.

There are **20 splits**: each of five test branches has four validation choices,
with the remaining three branches used for training. Both algorithms use seeds
41, 42 and 43, giving **40 selected configurations and 120 final evaluations**.
All splits use the same benchmark and frozen PBG embedding.

## Contents

- `protocol.json`: branches, hyperparameter candidates, seeds and training rules.
- `common.py`, `model_runner.py`, `run_experiments.py`: shared scoring, model
  execution, validation search and selected-configuration reproduction.
- `acquire_source.py`, `prepare_data.py`, `pbg_runner.py`: source and input builders.
- `data/`: frozen benchmark, source/input fingerprints, environment and hardware.
- `artifacts/`: local frozen embedding and coverage arrays, ignored by Git.
- `results/selected_models.json`: the 40 selected configurations and compact
  metadata for their three seeds, including validation cutoffs, epochs,
  signatures, checkpoint hashes and final metrics.
- `results/predictions/<test>/<validation>/<algorithm>_seed_<seed>.csv`:
  the 120 complete prediction files. Every split uses this same layout.
- `results/experiment.json`: input/code fingerprints, execution environment,
  counts, measured costs and historical provenance.
- `results/summary.csv`, `assignment_summary.csv`, `summary.json`: per-seed,
  per-assignment and aggregate results, generated by `summarize_results.py`.
- `REPORT.md`: combined results, all test/validation matrices and interpretation.

Detailed training histories and threshold-search records are runtime data.
The 320 historical fit records are under
`tmp/nalt-baselines/search/<test>/<validation>/<algorithm>/<configuration>/`.
Existing checkpoints remain at the `checkpoint` paths recorded in
`selected_models.json`. New runs write fit records, checkpoints, validation
scores and logs to `tmp/nalt-baselines/runs/`. Neither summary generation nor
selected-configuration reproduction depends on the historical search records.

## Protocol

The fixed population has **7,902 decisions**: 2,757 hierarchy-positive decisions
and 5,145 negatives encountered in retained LLM traversals. Demonstrations and
all five masked roots are excluded from scoring and supervision. Every cleaned
negative is retained; inverse training-class frequencies weight the loss.

| Branch | Positives | Negatives |
|---|---:|---:|
| Soil science | 1,032 | 952 |
| Pest management | 852 | 1,385 |
| Plant health | 219 | 1,282 |
| Immunology | 239 | 636 |
| Cell biology | 415 | 890 |

Decision identities are `(branch, concept URI)`: branch holdout is not entity
holdout. Seeds start included; every encountered non-seed receives a decision,
and only included nodes expand. Unreached scored nodes receive final EXCLUDE.
Model inputs use fixed label-free shortest BFS paths, retaining the seed and
path tail when truncated. Neither model consumes concept-label text.

One 200-dimensional PBG embedding is shared across every split and seed. All
five roots and incident edges are removed; directed SKOS broader, narrower and
related edges remain. No threshold-pruning preprocessing is used. Embedding
uses unlabeled structure from the full graph, including held-out concepts, so
this is transductive transfer. PBG settings are selected by sampled
link-prediction MRR and refitted on all embedding edges.

The original search evaluated six configurations per algorithm/split at seed
41. Selection uses validation F1, precision, recall, then fewer parameters;
remaining ties follow protocol order. Seeds 42 and 43 repeat that selected
configuration. Each seed selects its own cutoff over 0.00–1.00 in steps of 0.01,
using validation gated F1. Early stopping restores the best validation-loss
epoch. PA reference banks contain only training positives. No test score
selects configurations, cutoffs, seeds or assignments.

The complete search involved 240 candidate fits plus 80 seed repeats: 320 fits.
Reproducing only the selected configurations requires 120 fits.

## Environment and summary reproduction

Run from the repository root with a separate Python 3.10 environment:

```powershell
python -m venv tmp/nalt-baselines/env
tmp/nalt-baselines/env/Scripts/python -m pip install -r usecase/baselines/requirements.txt
tmp/nalt-baselines/env/Scripts/python usecase/baselines/summarize_results.py
```

The executed environment is recorded in `data/environment.txt` and
`results/experiment.json`: CPython 3.10.19, TensorFlow 2.12.0rc1 and CPU PyTorch
2.1.2. Model processes use four intra-operation threads and at most two workers.
The frozen embedding files must be present in `artifacts/`, with hashes matching
`results/embedding.json` and `results/artifacts.json`. They are local binary
inputs and are not included by Git.

## Reproduce selected models or repeat the search

Preparation checks the shared inputs. Running against the completed retained
experiment verifies its metadata and predictions and reuses it without training.

```powershell
tmp/nalt-baselines/env/Scripts/python usecase/baselines/run_experiments.py prepare
tmp/nalt-baselines/env/Scripts/python usecase/baselines/run_experiments.py run
```

Use a new output directory to train the 120 selected model/seed combinations.
This fixes the selected configurations but retrains each seed and reselects its
validation cutoff under the same protocol:

```powershell
tmp/nalt-baselines/env/Scripts/python usecase/baselines/run_experiments.py run --output-dir tmp/nalt-selected-reproduction --workers 2
tmp/nalt-baselines/env/Scripts/python usecase/baselines/summarize_results.py --output-dir tmp/nalt-selected-reproduction
```

To repeat all six candidates per split before selecting configurations:

```powershell
tmp/nalt-baselines/env/Scripts/python usecase/baselines/run_experiments.py search --output-dir tmp/nalt-search-reproduction --workers 2
tmp/nalt-baselines/env/Scripts/python usecase/baselines/summarize_results.py --output-dir tmp/nalt-search-reproduction
```

Interrupted runs resume from compatible runtime records. Completed outputs are
not overwritten. Use another output directory to start a new experiment. New
results retain compact selected-model metadata; intermediate records stay in
`tmp/`. Configuration selection and all seed-specific cutoffs are fixed before
held-out evaluation begins.

## Source and embedding reconstruction

PBG CPU retraining is not bitwise deterministic. Reuse the frozen arrays for
reproducing the reported classifier results. Reconstruct source/embeddings only
in a separate checkout without existing results or frozen artifacts.

Place upstream PBG commit `6fccd3f572f530469fe97ee63669524c686bcc2a` at
`tmp/nalt-baselines/vendor/PyTorch-BigGraph-6fccd3f572f530469fe97ee63669524c686bcc2a`.
The [pinned upstream source](https://github.com/facebookresearch/PyTorch-BigGraph/tree/6fccd3f572f530469fe97ee63669524c686bcc2a)
is unmodified; the wrapper seeds workers and uses Windows-compatible paths and
checkpoint copies.

```powershell
tmp/nalt-baselines/env/Scripts/python usecase/baselines/acquire_source.py
tmp/nalt-baselines/env/Scripts/python usecase/baselines/prepare_data.py
tmp/nalt-baselines/env/Scripts/python usecase/baselines/pbg_runner.py run
```

Acquisition verifies source hashes. Preparation writes benchmark/manifest files
under `data/` and regenerable edge lists/decision CSVs under `tmp/`. PBG refuses
to replace differing frozen embeddings. Use `search` with a new output directory
to build classifiers for newly reconstructed inputs.
